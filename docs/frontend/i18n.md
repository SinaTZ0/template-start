# Languages (i18n)

The app is Persian first: Persian (`fa`, right-to-left) is the base language, and English (`en`, left-to-right) is a
second one. Every piece of text a person reads is a message from [Paraglide JS](https://paraglidejs.com), a compiler
that turns each message into a typed function. A message is a plain function call, with no provider and no hook, so it
works the same in components, loaders, `head`, zod schemas and server code.

These are the rules. The page and feature steps link here from [frontend-flow.md](../frontend-flow.md) and
[backend-flow.md](../backend-flow.md).

## The Pieces

| Piece                | Where                                            | Job                                                                         |
| -------------------- | ------------------------------------------------ | --------------------------------------------------------------------------- |
| Project settings     | `project.inlang/settings.json`                   | The base locale, the locales, where the message files are.                  |
| Compiler config      | `project.inlang/paraglide.config.ts`             | How a request's locale is found, the URL patterns, excluded routes.         |
| Messages             | `messages/fa.json`, `messages/en.json`           | The text, one file per locale, the same keys in each.                       |
| Generated code       | `src/paraglide/` (gitignored)                    | `m.<key>()` functions and the runtime. Never edit; it's regenerated.        |
| Server middleware    | `paraglideMiddleware` in `src/server.ts`         | Finds each request's locale and keeps it for everything that request runs.  |
| URL rewrite          | `rewrite` in `src/router.tsx`                    | `/en/notes` reaches the `/notes` route; links come out with `/en`.          |
| Locale for API calls | `src/orpc/client.ts`, `src/lib/locale.server.ts` | The browser sends its locale in `x-locale`; the server reads it on `/rpc`.  |
| Formatting helpers   | `src/lib/locale.ts`                              | `formatNumber`, `formatDate` and friends, Open Graph codes, language names. |
| Switcher             | `src/components/shared/locale-switcher/`         | Links to the current page in each other locale.                             |

The Vite plugin compiles the messages in `pnpm dev`, `pnpm build`, Storybook and Vitest. `pnpm i18n:compile` does it
on its own, and runs before `tsc` in `pnpm typecheck` and after `pnpm install`. The first compile downloads the inlang
message-format plugin (pinned in `settings.json`) from jsDelivr and caches it in `project.inlang/cache/`.

`pnpm i18n:compile` writes the same file layout as `pnpm dev` (`--output-structure locale-modules`, one module per
locale). With the CLI's default (one module per message) every dev start after a typecheck replaced the files while
the server was loading them, and logged `Failed to load url /src/paraglide/messages/…`. `pnpm build` still writes one
module per message, so unused messages drop out of the bundle.

## How the Locale Is Found

- **Pages: the URL, and only the URL.** The base locale has no prefix (`/notes`), every other locale has one
  (`/en/notes`). There is no cookie and no `Accept-Language` redirect, so a shared link and a crawler always get the
  language the URL names. Changing language means going to the other URL.
- **On the server**, `paraglideMiddleware` resolves the locale once per request and keeps it in `AsyncLocalStorage`.
  `getLocale()` returns it anywhere in that request, including oRPC procedures that loaders call in-process during
  SSR.
- **In the browser**, `getLocale()` reads `window.location`.
- **`/rpc/*` has no locale in its path**, so the browser's `RPCLink` sends `x-locale: <locale>` and the
  `custom-locale-header` strategy reads it. A missing or unknown value falls back to the base locale.
- **Excluded routes** (`/api/*`, `/healthz`, `/robots.txt`, `/sitemap.xml`) are never redirected or prefixed. Better-Auth
  returns error codes, which the auth slice turns into messages (`src/routes/auth/auth-errors.ts`).
- **Routes are declared without a locale.** `src/routes.ts` and every `<Link to>` use the plain path (`/notes`). The
  router's `rewrite` strips the prefix on the way in and adds the current one on the way out, so links, preloading and
  redirects keep the visitor's language.

## Writing Messages

- **Every piece of text a person reads is a message**: labels, headings, button text, placeholders, `aria-label`s,
  `sr-only` text, alt text, toasts, page titles and descriptions, form and API error messages. Code identifiers, logs
  and developer diagnostics stay in English and are not messages.
- **Add the key to every locale file.** `fa.json` is the reference: write the Persian first, then the English. A key
  missing from a locale falls back to the base locale's text, which is the bug a reviewer looks for.
- **Key names are flat snake_case, prefixed by their owner:**

  | Prefix             | For                                            | Example                          |
  | ------------------ | ---------------------------------------------- | -------------------------------- |
  | `common_`          | Words several places share, primitives' labels | `common_close`, `common_loading` |
  | `site_`, `nav_`    | Site identity, the header and footer           | `site_name`, `nav_notes`         |
  | `<slice>_`         | One route slice                                | `notes_empty`                    |
  | `<feature>_error_` | Messages the API sends (validation, outcomes)  | `note_error_title_required`      |

  Name a key after what it is, not where it sits on the screen (`notes_delete_confirm`, not `notes_button_2`). Delete a
  key when its last use goes.

- **Values are parameters**, never string concatenation: `"notes_delete_label": "حذف «{title}»"`, called as
  `m.notes_delete_label({ title })`. Word order differs between languages, so a sentence is always one message.
- **Numbers are formatted by the message.** Pass the number; declare it as `number` in the message, which gives Persian
  digits and separators in Persian (`۱٬۲۰۰`) and `1,200` in English:

  ```json
  "note_error_title_too_long": [
    {
      "declarations": ["input max", "local maxText = max: number"],
      "match": { "": "عنوان حداکثر {maxText} حرف است." }
    }
  ]
  ```

- **Plurals** are variants. Persian doesn't change the noun after a number, so its message has one variant; English
  picks one with `plural`:

  ```json
  "notes_count": [
    {
      "declarations": ["input count", "local countPlural = count: plural", "local countText = count: number"],
      "selectors": ["countPlural"],
      "match": { "countPlural=one": "{countText} note", "countPlural=other": "{countText} notes" }
    }
  ]
  ```

### Never Call a Message at Module Scope

A module is evaluated once per server process. A message called at its top level is frozen in the locale of whatever
ran first, and every later request, in any language, gets that text. Call messages when the text is needed: in render,
in a handler, in a function.

```ts
// Wrong: evaluated once, in one locale, for every request
const NAV_ITEMS = [{ label: m.nav_home(), to: "/" }];
const titleSchema = z.string().min(1, m.note_error_title_required());

// Right: store the message function, call it in render
const NAV_ITEMS = [{ label: m.nav_home, to: "/" }] as const; // {item.label()}

// Right: zod calls `error` each time a check fails
const titleSchema = z.string().min(1, { error: () => m.note_error_title_required() });
```

The same holds for anything that becomes text later: export a function (`rateLimitedMessage()`), not a string
constant.

## Messages from the API

The API sends finished text in its error data (`errors`, `fields`), and `describeApiFailure` shows it as it is
([backend/architecture.md](../backend/architecture.md) → Errors are uniform and safe). That text is in the request's
locale:

- Validation schemas (`validation.ts`) and form schemas (`schema.ts`) give every check an `error` function.
- A service that returns field messages calls the message when it builds the outcome
  (`fields: { imageMediaId: m.note_error_image_unusable() }`).
- The `message` of a contract error (`commonErrors`, `authErrors`) is a developer diagnostic in English. It never reaches
  a form.

## Numbers, Dates and Direction

- **Numbers and dates outside messages** go through `formatNumber(value)` and `formatDate(value, options)`
  (`src/lib/locale.ts`). They use the current locale, so Persian gets Persian digits and the Jalali calendar. Never
  build an `Intl` formatter with a fixed locale. The same file has `formatDateRange` (a span, without repeating what both
  ends share: "December 15 – 19"), `formatDateParts` (day, month and year apart, for a date tile) and `formatRelativeDays`
  («فردا», "in 3 days"). A calendar date stored without a time (`2026-10-30`) becomes a `Date` through `isoToDate`,
  at UTC noon, so it's the same day in every time zone.
- **Input** is normalized whatever the page's language: `toLatinDigits` before parsing a number, `persianText()` for free
  text ([backend/architecture.md](../backend/architecture.md) → Free text is normalized).
- **Direction** comes from the locale: `<html lang dir>` and Base UI's `DirectionProvider` read `getTextDirection()` in
  `__root.tsx`. Components never assume a direction:
  - Use logical classes only: `ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`, `text-start`, `rounded-s-`. Physical ones
    (`ml-`, `left-`, `text-left`) put things on the wrong side in one of the two languages.
  - Icons that point forward or back flip with the direction. Pick the icon for Persian and flip it for left-to-right
    text: `<ArrowLeftIcon className="ltr:-scale-x-100" />` points left in Persian and right in English (`home.tsx`).
  - Text that is always left-to-right (emails, URLs, phone numbers, codes) is set `dir="ltr"` in both languages.
- **Content** (a note's title, a user's name) is stored as typed and isn't translated.

## Links and Switching Language

- Use `Link` with the plain path. The rewrite keeps the visitor's locale.
- A link to a specific locale, outside the router, uses `localizeHref(path, { locale })`.
- The switcher (`locale-switcher`, in the header) renders a plain `<a>` per other locale, pointing at the current page
  in that locale (`hrefLang` and `lang` set). Following it loads the page again in the new language: every message,
  `lang` and `dir` then come out right without re-rendering anything. With only one locale, it renders nothing.

## SEO

`pageMeta` (`src/lib/seo.ts`, [seo.md](./seo.md)) builds the locale tags itself:

- The canonical URL and `og:url` are the page in the current locale (`/en/notes` for English).
- `og:locale` is the current locale's code (`fa_IR`, `en_US`), with `og:locale:alternate` for the others.
- Public pages get `<link rel="alternate" hreflang="…">` for every locale, plus `x-default` pointing at the base
  locale.
- The sitemap lists each page once per locale, each with its alternates.

`title` and `description` passed to `pageMeta` are messages, called in `head`.

## Adding or Removing a Language

**Adding** (say Arabic, `ar`):

1. Add it to `locales` in `project.inlang/settings.json`, and to both `urlPatterns` entries in `paraglide.config.ts`
   (`["ar", "/ar"]`, `["ar", "/ar/:path(.*)?"]`), above the base locale's line.
2. Copy `messages/en.json` to `messages/ar.json` and translate every value.
3. Add its Open Graph code to `OG_LOCALE` and its own name for itself (`العربية`) to `LOCALE_NAMES`, both in
   `src/lib/locale.ts`.
4. Check it in both directions: an RTL language needs nothing more if the components use logical classes.

**Persian only**, for a project that doesn't need a second language:

1. Remove `en` from `locales` and from the `urlPatterns` entries, and delete `messages/en.json`.
2. Remove its entries from `OG_LOCALE` and `LOCALE_NAMES`. The switcher then renders nothing and `pageMeta`
   leaves out the alternates. Delete the English e2e check (`e2e/locale.spec.ts`).

Keep everything else: messages, `formatNumber`, logical classes. Adding a language later is then only the steps above.

## Checklist for a New Page

1. Every text on the page, its `head` title and description, and its form and API messages are messages in every
   locale file, called at render or request time.
2. Numbers and dates go through the message's `number` declaration, `formatNumber` or `formatDate`.
3. Layout uses logical classes, and directional icons flip. Look at the page in both `/…` and `/en/…`.
4. Links use `Link` with the plain path.
